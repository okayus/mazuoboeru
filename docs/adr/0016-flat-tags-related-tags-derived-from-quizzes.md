# タグをフラットに戻し、タグ間の関係は保存せず公開クイズから導出する（ADR-0007 タクソノミを supersede）

> **Status: accepted（設計確定・2026-08-21 grill）。** 本 ADR はモデルの判断を確定する。`tag_edge` の物理 DROP・コード撤去・API 変更は引退 PR（人間 merge・ホスト backup 後）、タグ探索グラフ UI は続くグラフ PR で実装する（Consequences「実装の切り方」）。[[CONTEXT.md]] の用語改訂（[[Tag]] 改訂・[[Related Tags]] 追加・Tag Taxonomy／Effective Tags 引退）は本 grill で実施済み。

## Context

[[0007-tag-subsumption-taxonomy]]（2026-06-17）は、フラットな [[Tag]] に**タグ間の有向「上位/下位」関係を保存する** `tag_edge`（運用者が curate する DAG）を足し、そこから**実効タグ**（authored＋上位閉包）を導出して、広いタグ検索の下位一致・ダッシュボードのロールアップ・「広い/絞り込む」チップに使っていた。

2 か月運用した事実（2026-08-21 に本番 API とコードで確認）:

- **`tag_edge` は投入初日の 1 本（`HTTP ⊂ Protocol`）のまま増えていない**。curate の経路（`wrangler d1 execute`）は最初の 1 回しか使われなかった。
- 一方で作者のタグ付けは活発で、新着 50 件だけで **115 タグ・550 の共起ペア**、1 クイズあたり 3〜10 タグ。作者は「広い語も狭い語も自分で同列に付ける」（`web基礎`/`todoアプリ` のようなシリーズ名、`HTTP`+`rest`+`api` の併記）。
- 実データの問題は上位下位では表せないものだった: 同義・言語ゆれ（`security`/`セキュリティ`、`frontend`/`フロントエンド`）は DAG では**相互 subsumption＝巡回**で表現不能、シリーズ/難度ラベルのハブ化は階層ではなく重みの問題。

きっかけは**タグ探索グラフ UI**（タグを選ぶと一緒に付いていないタグが消え、複数タグで絞り込み、人気タグが大きく見える）の構想。ここで「グラフの素材は DAG ではなく共起」であることが明確になり、ユーザが方針を変えた——**「タグ同士は互いを知らない。タグが付けられているクイズによって、関連があることが外部から確認できればよい」**。DAG の上に共起を重ねると、保存された有向関係と導出された無向関係の 2 種類を抱え、ADR-0007 自身が中心論点と呼んだ「他人のクイズの実効タグまで一斉に変えるグローバル副作用＝共有語彙の curate」も背負い続ける。

## Decision

- **タグはフラット。タグ間の関係はいかなる種類も保存しない**（上位下位・エイリアス・関連のいずれも）。`tag_edge` を **DROP**（migration 0012。`tag` を参照する子テーブルで他テーブルへのカスケードは無し。失う行は `HTTP ⊂ Protocol` の 1 行＝意図的に捨てる）。`worker/domain/tag-graph.ts`・実効タグの導出・関連コードを撤去する。
- **タグ間の関連は [[Related Tags]]（関連タグ）として読み時に導出する**: 選択中のタグ（1 個以上）をすべて持つ**公開中**（`status='published' AND deleted_at IS NULL`）のクイズに一緒に付いている選択外のタグ、件数はそのようなクイズの数。**保存しない**。単一タグの関連も複数 AND の絞り込みも同じ一つの概念。
- **公開タイムラインの絞り込みは `?tags=a,b`**（カンマ区切り・正規化キーで**完全一致**・AND）。旧 `?tag=`（下位展開）と `related:{broader,narrower}` は廃止し、応答は **`related: [{name, count}]` を常に返す**（選択が空なら全タグの件数＝人気一覧）。未知のタグは従来どおり空結果。
- **ダッシュボードのタグ別集計は作者が付けたタグ（authored）そのもので束ねる**（[[0006-dashboard-aggregation-semantics]] を追記で改訂）。1 クイズの各タグへの多重計上と「タグなし」バケツは不変。
- **タグ探索グラフ**: ノード＝タグ（大きさ＝公開クイズ数）、エッジ＝共起（無向）。データは公開エンドポイントが返す**対応表**（公開クイズ→タグ集合＋タグ一覧、50 件上限なし）で、件数・共起・AND 絞り込み・Related Tags・該当一覧は**クライアントの純粋関数**で導出する（ペア共起だけでは 2 個以上選んだときの Related Tags を正確に出せないため対応表を返す）。同じ純粋関数をサーバの `?tags=`／`related` でも使う＝**`packages/core`（`@mazuoboeru/core`）を新設して置く**（初のクライアント/サーバ共有ロジック。将来 CLI も使える）。
- **作らないもの**: カテゴリ／階層、同義タグのエイリアス・統合、運用者が curate する共有語彙。同義・ハブはグラフにそのまま見える（重み付けは描画の関心事で、モデルは触らない）。必要になれば別 ADR。

## Considered Options

- **DAG を残し共起を重ねる**: 保存（有向）と導出（無向）の 2 種類の関係・curate 負担・2 つのコード経路が残る。DAG は 2 か月で 1 本のまま＝コストに見合う価値が出なかった。却下。
- **コードは消しテーブルは読み専用で温存**: 「タグは互いを知らない」と矛盾し、死んだ経路が残る（Attempt 引退＝[[0013-retire-attempt-unify-answers]] と同じ理由で完全引退）。却下。
- **同義タグの統合（alias／merge）を今やる**: `quiz_tags` の書き換えは他人のクイズへの不可逆グローバル副作用。先にグラフで「何を掃除すべきか」が見えてから別 ADR で判断。持ち越し。
- **タグに種別（topic／series／level＝facet）を導入**: データモデル変更。ハブ化は描画の重み（生件数／Jaccard 等）で扱えるので見送り。
- **グラフはサーバが nodes/edges を集計し絞り込みは毎回 `?tags=`**: 初期描画は軽いが選択のたびに往復し、ペア共起ではクライアント側で正確な AND が出せない。現規模（数百クイズ）では対応表のほうが単純。大規模化時の退路として残す。
- **共有関数の置き場**: `apps/web/shared/`（同一パッケージ内の新フォルダ）／`worker/domain` を `src/` から値 import／**`packages/core` 新設（採用）**。採用理由は CLAUDE.md の「`packages/core` はロジック発生時に追加」を初の共有ロジックに適用すること。

## Why

- **観測された使われ方に合わせる**: 作者は広い語も狭い語も自分で付けており、構造はクイズ側に既にある。運用者が別に階層を育てる必要がなかった。
- **グローバル副作用を持つ仕組みを消す**: 導出される関連は、すべて「ある作者が自分のクイズに付けたタグ」の帰結で、クイズが消えれば寄与も消える。UGC の信頼境界は**クイズ単位**に閉じ、ADR-0007 の中心懸念（他人のコンテンツの間接ラベリング・閉包肥大化）は成立しなくなる。
- **概念が 1 つで足りる**: Related Tags（選択集合に対する定義）だけで、タイムラインのチップ・複数 AND・グラフの絞り込みを同じ関数で賄える。
- 純粋関数へ寄せる構成（関数のみ・I/O は境界）は従来どおり。

## Consequences

- **[[0007-tag-subsumption-taxonomy]] は superseded**（同 ADR に前方ポインタ）。**[[0006-dashboard-aggregation-semantics]] の「実効タグで束ねる」は authored へ改訂**（追記）。
- **失うもの**: curate による上位ロールアップ（「programming で全言語をまとめて見る」）。作者が広い語を自分で付けない限り出ない。受け入れる。
- **本番の振る舞い差**: `?tag=Protocol` に HTTP のクイズが含まれなくなる／ダッシュボードから導出の「Protocol」バケツが消える。エッジ 1 本ぶんで実質ゼロ。
- **漏えいの守り**: `quiz_tags` は [[Draft]] 作成時にも書かれる。導出される集計（件数・共起・Related Tags・グラフ）は**必ず公開クイズに join**し、純粋関数には公開クイズの対応表だけを渡す（draft／hidden の存在が件数から漏れない）。
- **実装の切り方**: **引退 PR**（migration 0012 DROP・コード撤去・`?tags=` AND＋`related` 配列・Timeline チップを Related Tags 化・`packages/core` 新設と純粋関数・`docs/data-model.md`／status の改訂）は **`Relay-Merge` を付けず人間 merge**（DROP を含むのでホストが `wrangler d1 export` で backup してから merge＝Workers Builds が自動適用）。**グラフ PR**（`GET /api/public/tag-graph`・`#/tags` ページ・d3-force＋React SVG）はその上に載せる。データモデル docs は引退 PR で改訂する（docs を prod に先行させない＝ADR-0013 と同じ）。
- **残る課題（モデルは触らない）**: 同義タグ（`security`/`セキュリティ`）は別ノードのまま並ぶ、シリーズ/難度ラベルはハブになる。前者は alias の別 ADR 候補、後者は描画の重み付けで扱う。
